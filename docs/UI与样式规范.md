# UI 与样式规范

本规范适用于语文、数学、英语、个人中心及后续新增功能。它集中整理 README、需求确认稿和各主题实现文档中的公共 UI 约定，并作为后续功能开发与样式调整的统一依据。

**新增功能必须优先复用公共组件、CSS 变量及响应式规则，不得按学科或阶段重新复制一套 UI。** 调整公共规范时，应同步更新本文、公共实现与回归测试。历史验收文档中的旧截图、数值及旧版导航描述不覆盖本规范。课程规划、学习记录、奖励规则仍由各自文档维护。

## 1. 实现入口与职责

| 入口 | 职责 |
| --- | --- |
| `src/ui-theme.css` | 公共视觉令牌、布局断点、卡片、按钮、选择题、反馈、工具栏及跨学科适配；在 `app.js` 中最后导入，统一兼容既有组件类名 |
| `src/learning-ui.js` | `learningPosition`、`learningCardFooter`、`learningAnswerLabel`、`learningTools`、`pinyinToggle` 等共享 HTML 组件 |
| `src/learning-ui.css` | 按组件角色定义的学习字号、拼音开关与标题区域布局 |
| `src/reading-layout.js` | 按实际换行与注音情况，为同一行学习内容或选项保留统一注音空间 |
| `src/navigation.js` / `src/navigation.css` | 阶段、主题、玩法、目录搜索及手机导航 |
| `src/icons.js` | 本地 SVG 图标；同义操作复用同一图标 |
| 各学科 CSS | 仅补充笔顺、田字格、竖式、拼音四线格、英文拼词等教学展示，及必要的内容布局 |

`ct-sentence-topic`、`ct-sentence-card` 等既有类名兼容所有语文、数学主题的同一套学习卡样式，不再代表只给第二阶段使用的另一套 UI。

## 2. 视觉方向与令牌

- 保持奶油色页面、纸面学习卡、柔和粉紫、薄荷绿及米色提示区，不引入独立的学科主题皮肤。
- 公共颜色、圆角、阴影、卡片内边距和侧栏宽度使用 `--ui-*` 变量，不在新模块里写另一份近似值。
- 学习卡使用 `--ui-surface: #fffdfb`、`--ui-card-border: #d9bfca`、`1.5px` 边框、`22px` 圆角及 `0 5px 0 #eadddf` 阴影。
- 选中态使用粉紫色 `--ui-selected-*`；例句和参考使用米色 `--ui-example-*`；开放活动使用浅绿 `--ui-activity-*`。
- 未作答提示使用淡粉紫 `--ui-feedback-*`；正确使用浅绿 `--ui-success-*`；错误、重试、跳过查看答案使用浅橙 `--ui-warning-*`。
- 颜色必须与文字、图标或状态说明共同表达含义，不仅依靠颜色区分对错和选中状态。

## 3. 导航、页面与响应式布局

### 内容层级

- 内容按“阶段 → 主题 → 小分类”组织，学习卡和题目属于小分类，不再增加一层内容导航。
- 桌面主题导航保持单行，溢出时横向滚动，并提供可搜索目录；手机使用已有下拉入口。
- 仅有一个阶段时可以直接展示主题，阶段说明放在页标题上方；不添加无内容入口。
- 各学科、阶段和玩法保留已有选择，不因视觉统一清除学习记录或修改内容标识。
- 拼音玩法保留“认识拼音、趣味练习、巩固提高”的分组。错题本、收藏、记录和奖励入口位于成长花园及“我的”，不冒充课程主题。

### 公共布局

| 屏幕宽度 | 主内容与侧栏 |
| --- | --- |
| 大于或等于 `1600px` | 双栏，侧栏 `300px`，间距 `32px` |
| 大于 `1200px` 且小于 `1600px` | 双栏，侧栏 `272px`，间距 `27px` |
| 大于 `1000px` 且小于或等于 `1200px` | 双栏，侧栏 `242px`，间距 `20px` |
| 小于或等于 `1000px` | 主学习区改为单栏，成长花园和附属卡片放在下方，不允许各学科使用不同的单双栏断点 |
| 小于或等于 `600px` | 附属卡片也改为单栏，公共卡片内边距收紧至纵向 `19px`、横向 `17px` |

- 使用 `.learning-layout`、`.learning-main`、`.learning-aside`；既有 `.hz-layout`、`.ph-layout` 由公共样式兼容。
- 所有网格子项允许收缩，长句、英文长词与选项可以换行；`320px` 宽度下也不得产生整页横向溢出。
- 英语在窄屏上保留紧凑“学习目录”按钮，默认收起课程地图，展开后限高滚动；选择课程后收起目录。桌面地图正常展示。
- 手机学科导航继续使用抽屉，不因为统一学习区断点改变应用外壳的导航方式。

### 页头与滚动

- 页头顺序统一为阶段说明、页面标题、简介；辅助开关在右侧，手机可放在阶段说明同一行。
- 桌面页标题基准为 `30px`，简介为 `14px`；英语保留字母装饰与教学标签，不另设更大的页标题。
- 切换学科或主题后回到页面顶部；当前学习卡内的标记、作答、翻页和辅助开关不得一律强制回页首。
- 目录浮层不撑高头部；保留已有键盘、鼠标和触屏操作。

## 4. 字号与教学例外

| 组件角色 | 大于 `600px` | 小于或等于 `600px` |
| --- | --- | --- |
| 学习内容列表、英语单词列表 | `18px` | `16px` |
| 普通选择题答案 | `18px` | `16px` |
| 语文、数学学习卡内容标题 | `24px` | `22px` |
| 位置计数 | `12px` | `12px` |
| 公共按钮、题数设置 | `12px` | 以公共组件的紧凑样式为准，不小于已有按钮可点击区域 |

- 字号按组件角色确定，不再按标题字数分档，不能因内容是长句就临时覆盖同类列表字号。
- 正文、说明文字与教学展示使用各自合适的字号；**不能把田字格、单字演示、拼音主展示、英文词卡大词、诗文、故事和竖式一律缩成普通列表字号。**
- 使用系统字体与本地资源，不请求外部字体服务。

## 5. 学习卡、列表与位置计数

- 学习主卡复用 `.study-card`，练习主卡复用 `.quiz-card` / `.ph-quiz`，结果卡保留本轮真实统计，不伪造“全部掌握”。
- 学习卡顶部使用图标分类徽章 `.category-badge`，右侧使用 `learningPosition`；英语 `.ph-badge` 使用同一视觉规范。
- 学习位置为“第 n / 总数 项”，练习位置为“第 n / 总数 题”；底部不再重复放位置圆点或计数。
- 查字说明、故事、无逐项浏览的说明卡及结果页不强加位置计数；用于跳转和作答状态的题目导航可以保留。
- 本节学习卡列表统一放在当前主卡下方 `.learning-lesson-map`，不再挤在卡片正文上方。英语课程地图和本轮单词列表保持不同职责。
- 例句使用米色容器，活动或“说一说，试一试”使用浅绿色容器；参考答案的展开按钮保留 `aria-expanded`，不因样式统一自动评分开放表达。

## 6. 按钮与图标

- 普通操作使用 `.outline-button`，轻量自评与辅助操作使用 `.soft-button`，明确提交、开始或继续操作使用 `.solid-button`；英语既有 `.ph-button` 及变体由公共样式兼容。
- 最小按钮高度为 `44px`，圆角为 `11px`。不能通过缩小点击区域适配窄屏。
- “我认识啦 / 练练这一节”同排居中，使用浅绿与淡粉紫轻量按钮，分别配勾选和铅笔图标；主卡底部另设虚线分隔的左右翻页区。
- 英语“我会读了，下一词”仍保留标记并前进的行为，但使用同一轻量按钮；“上一个 / 下一个”使用描边按钮，不再单独使用深色实心翻页按钮。
- 操作箭头使用 `icon('chevron')`，上一项通过 `.previous` 翻转；勾选、收藏、声音、刷新等使用共享 SVG，不混用文字箭头模拟同一操作图标。
- 禁用项保留 `disabled`，切换项正确维护 `aria-pressed`；不能用灰色外观代替禁用行为。
- 教学内容中的字母合音箭头、部件位置线条等属于内容，不要求替换为操作图标。

## 7. 练习、工具栏与反馈

- 普通选择题统一 `.answer-grid`、`.answer-option` 与 `learningAnswerLabel`，依次标记 A/B/C/D；答案内容独立包裹，长句可以换行。`600px` 及以下改为单列。
- 可访问名称使用答案原文，选项字母设为 `aria-hidden`；不要让读屏把字母当成答案的一部分。
- 已揭晓的正确选项保持清晰可见，错误项保留明确提示。拼写、配对、听辨播放按钮不强行改成选择题。
- 反馈使用 `.answer-feedback` 和 `role="status"`；待作答时就提供提示，不留一块意义不明的空区。正确使用 `.success`，错误、重试和跳过查看答案使用 `.warning`。
- 查看答案不冒充独立答对；重试不覆盖首次成绩；主题隔离、错题移出条件及奖励规则不因 UI 调整改变。
- 语文与数学的题数工具栏复用 `learningTools`，只在练习页出现；`10/20/30` 题按钮高度、字号、选中态与下一轮说明一致。
- 英语保留现有 `5/10/20` 题和当前轮次规则，不为了工具栏外观统一修改业务含义；选框、说明和重新开始按钮使用共享尺寸与间距。

## 8. 拼音辅助与注音排版

- 复用标题区 `pinyinToggle`，统一显示“拼音”，使用 `role="switch"`、固定可访问名称“拼音辅助”及 `aria-checked`。
- 手机开关与阶段说明同排，不额外占据一整条工具栏；数学不增加无作用的拼音开关。
- 注音使用原生 `ruby` / `rt` / `rp`，不破坏完整词组和多音词的现有注音数据。
- `observeReadingRows` 按实际换行计算注音预留空间。同一行有注音时，整行统一留高；整行无注音时不留空白；窗口变化、开关切换与字体就绪后重新计算。
- 不用固定高度或整页统一加大顶部空白来掩盖注音对齐问题；汉字、词语与注音不得超出按钮边框。

## 9. 无障碍、音频、弹窗与动态效果

- 所有操作支持键盘，保留可见焦点、可访问名称和真实控件语义；触屏操作不能只依赖悬停。
- 页面正文、按钮和状态提示必须可读，不用过浅文字承担必要信息，不仅依靠动效传达完成状态。
- 示范音频使用现有本地资源；保持播放、慢速、加载、失败状态，切换学习内容时停止上一段，避免叠音。没有音频或麦克风时不能阻断学习。
- 弹窗沿用现有关闭、Esc、返回及二次确认机制；奖励预览、规则说明返回时恢复原分类、滚动位置和焦点，不能套用主题切换回页首的逻辑。
- 尊重系统及应用已有的减少动态效果设置，不添加无法关闭的强烈闪烁或无业务价值的重复动画。
- 奖励物品摘要、问号、预览与庆祝的专门交互遵循 [奖励规则与扩展约定](奖励规则与扩展约定.md)，与本规范的公共按钮和无障碍要求共同生效。

## 10. 后续开发与验收清单

1. 开发前确认公共组件是否已有相同职责；新页面按本规范选择组件，不复制既有样式后修改几个色值。
2. 公共变化修改 `ui-theme.css`、`learning-ui.*` 或导航组件；学科文件仅放必要教学展示。避免不断提高选择器优先级或使用 `!important` 修补冲突。
3. 需要新组件或新令牌时，先明确用途与已有组件的差别，同步补充本文及对应测试。
4. 至少检查 `1440px` 桌面、`1050px` 断点上方、`1000px` 断点、`820px` 平板、`390px` 手机和 `320px` 窄屏。
5. 验证卡片、按钮、选择题、反馈、目录开合、翻页边界、注音开关、滚动行为及键盘操作；教学内容不能裁切或横向溢出。
6. 检查标记、首次答题、跳过、重试、刷新恢复、错题与奖励，确认只调整表现，不改变业务规则。
7. 检查真实浏览器截图，而不只检查 CSS 字符串。截图与测试产物放在已忽略目录，不提交到源码。
8. 运行相关单元测试、浏览器测试、生产构建及 `git diff --check`。报告实际执行范围；环境失败或未验证浏览器不能写成已通过。

重点回归入口：`tests/browser/ui-consistency.spec.js`、`learning-actions.spec.js`、`learning-content.spec.js`、`reading-alignment.spec.js`、`pinyin-layout.spec.js`，以及各学科原有交互测试。
