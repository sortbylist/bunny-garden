# 教学音频试听审核

## 审核入口

- 在已运行的小兔学习乐园站点地址后加 `/audio-review/`。本地开发默认地址为 `http://127.0.0.1:5173/audio-review/`。子路径部署需保留站点前缀，例如 `/rabbit-garden/audio-review/`。
- 审核页有独立构建入口。学习页面和根 README 不提供跳转入口。审核页随静态站点提供，知道地址即可打开。
- 本轮操作保存在当前页面内存中。切换学科、筛选和翻页时保留，关闭或刷新页面会清空本轮操作。需要中途结束时先导出。刷新后会加载项目中已写回的审核结果。

## 清单与批次

先选学科，再按阶段、主题、分类筛选。切换批次可集中审核一类音频。相同文件出现在不同教学用途时可以分别标记结果。

| 批次 | 范围和检查项 |
| --- | --- |
| 慧慧整词录音 | **写字、蓝天、大树、大海、河水、小鸟、小鱼、白兔、山羊、黄牛**。试听正式学习页使用的整词录音，可与原逐字音频对照。检查清晰度、连读变调、轻重和节奏。 |
| 慧慧借音对照 | 全部 34 张借音卡，包括 23 张声母卡和 11 张韵母卡。逐张试听慧慧读出的借用音节和学习页现用录音，判断呼读音和韵母听感是否适合教学。 |
| 借音拼读组合题 | 花、瓜、多、熊 4 道拼读题。使用学习页现用录音，先点「听分解」，再听完整音节。 |
| 其余拼音录音 | 对照卡片、题目或声调示例试听学习页现用录音。检查声调、轻声、变调、停顿和清晰度。备用音节标出可能使用的词语。 |
| 古诗示范朗读 | 20 首，逐首核对诗名、朝代、作者和原文。检查多音字、断句、停连和节奏。此批可独立开展。 |
| 自然拼读 | 按课列出词卡和故事。核对实际音频、目标词或故事文本、英式英语读音和可懂度。 |
| 校园英语 | 按主题列出词汇、课堂指令、情景对话和使用音频的练习题。核对读音、原文、语境、语气和题目是否相符。 |

原先缺整词录音的 13 个双字词均已使用慧慧音频。白云、小草、画画已确认通过，已从待审核列表移除，剩余 10 个整词默认同页显示。

语文清单覆盖拼音学习卡、字词和相关练习用到的录音，以及备用音节与 20 首古诗。部分练习会复用学习卡录音。声调示例、听辨题与拼读题可按各自教学场景分别审核同一文件。

### 慧慧音频来源

慧慧音频由 Windows `System.Speech` 和 `Microsoft Huihui Desktop` 离线合成，参数与古诗相同，语速 `-1`，音量 `100`。整词 WAV 与 SHA-256 清单在 `public/audio/review/huihui/`，通过 `public/audio/manifest.json` 接入正式学习页。借音对照 WAV 与清单在 `public/audio/review/huihui-borrowed/`。

借音候选合成的是完整音节，清单记录输入文字及显式指定的读音。`i` 和 `y` 共用 `yī`，`u` 和 `w` 共用 `wū`，因此 34 张卡对应 32 段慧慧 WAV，审核结果按卡记录。试听时重点比较声母起音及长度，以及韵母部分的清晰度。候选仅供试听审核，学习页继续使用现有借音录音。四声与拼读沿用正式录音，其中 `má` 使用 Wikimedia Commons 收录的真人录音，`ong` 使用 OpenLearn 录音片段。

需要重生成时，在项目根目录用装有该语音的 Windows 执行以下命令。内容和校验值匹配的 WAV 会复用。

```powershell
powershell.exe -NoProfile -NonInteractive -ExecutionPolicy RemoteSigned -File scripts/generate-review-samples.ps1
npm run audio:download
```

## 审核与导出

1. 播放音频，然后对照预期读音和实际学习场景。需要时重听或点「停止播放」。
2. 每项选「通过」「需修改」或「待复核」。默认是「未审核」。选「需修改」时必须写明问题，其他结果可选填备注。建议写明第几段、哪个字或哪一句受影响。
3. 点「导出审核结果（JSON）」。文件包括当前学科所选批次的全部条目，阶段、主题、分类筛选和分页只影响显示范围。「全部批次」导出当前学科的全部批次。允许导出未审核的条目，方便分阶段提交。
4. 将下载的 JSON 提交给负责后续处理的 LLM，按下文的处理规则更新源码和审核清单。

试听清单默认每页显示 20 项，可切换为 8、50 或 100 项。有多页时，可在「每页数量」旁或清单底部翻页。「批量审批当前页」按当前筛选与分页范围统一应用结果，默认只处理未审核项。取消勾选「仅处理未审核项」可更新本页已有结果。批量标为「需修改」时须填写问题，已有的单项备注会保留，其余条目采用批量备注。

导出格式为 `bunny-garden-audio-review`，版本 `2`。顶层记录导出时间、范围、总数和已标记数量。文件采用紧凑 JSON，保留整批条目及其稳定标识，以下数组索引均从 `0` 开始。

- 学科取自 `scope.subject`。每个条目的 `locationIndex` 指向 `locations` 中的阶段、主题和分类。单批次的批次取自 `scope.batch.id`，导出全部批次时取自对应的 `locations` 记录的 `batch`。
- `expected` 省略时使用 `title`。`status` 省略时为 `unreviewed`。`approved`、`needs-change`、`recheck` 分别对应「通过」「需修改」「待复核」。有备注时，`noteIndex` 指向 `notes`，同一段批量备注只存一次。
- `audio` 中的每个动作按 `clipIndexes` 的顺序读取 `clips`。片段记录资源路径、指向 `sources` 的 `sourceIndex`，以及音频清单提供的合成文字或 SHA-256。`reference: true` 表示该动作只用于对比，省略时为 `false`。

## LLM 处理审核结果

收到 JSON 后，按 `items[].id` 定位审核条目，结合课程位置、预期内容、音频路径和备注核对。按处理结果更新涉及的源码、音频或资源清单，同时将最终状态和备注写入 `src/audio-review-decisions.js`，以条目 ID 为键。可用 `sha256` 将确认结果绑定到主播放动作的首个片段，音频指纹变化后该条目会重新出现在清单中。

| 导出结果 | 源码和审核清单处理 |
| --- | --- |
| `approved` · 通过 | 在审核清单记录该条目已通过，并从待审核列表移除。学习页继续使用已通过的内容和音频。同一文件在其他教学场景的审核结果按各自条目的 ID 处理。 |
| `needs-change` · 需修改 | 保留条目和备注，标为「需修改」。按备注修订相关内容或音频后，改为「待复核」，在同一教学场景复听。 |
| `recheck` · 待复核 | 保留条目及备注，在审核页标为「待复核」，等人工复听确认。 |
| `unreviewed` · 未审核 | 跳过该条目，沿用审核清单已有状态。 |
