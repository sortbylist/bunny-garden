# 本机数据备份与兼容约定

## 统一存储与备份长期规则

以下规则适用于全部现有学科、公共功能和后续新增模块。

1. 配置、昵称、学习进度、练习过程、错题、收藏、草稿和奖励等全部本机持久化信息必须纳入同一个应用根数据对象，按模块字段组织。
2. 统一使用 `src/storage.js` 中的应用存储键和 `saveState` 入口。模块通过根对象中的对应字段与公共保存回调读写本模块的数据。
3. 导入、导出、恢复默认状态和清空操作均针对完整根对象。新增模块的数据必须自动包含在完整备份中。
4. 模块可以有各自的数据校验及默认值，但必须通过根数据的统一加载流程执行。保存任何模块时都应包含其他模块的最新状态，禁止各自序列化旧快照后覆盖根数据。
5. 新增字段或模块时，同步更新根数据默认值、字段校验和测试；验证跨模块保存、刷新恢复、清空后继续学习及完整导入导出，确保没有遗漏或互相覆盖。

## 使用方式

在侧栏“学习设置”中选择“导出全部数据”，下载一个 UTF-8 JSON 文件；换设备或浏览器后，在同一位置选择“导入备份文件”。文件只在浏览器本机生成和读取，不上传、不需要账户。

导入先校验文件，再显示覆盖确认。确认后完整替换本机根数据并刷新页面。建议覆盖前先导出当前记录。取消、文件损坏或不支持的版本均保留原记录。文件大小上限为 20 MB，可能包含昵称和写作草稿，请妥善保管。

## 覆盖范围

所有数据统一保存在 localStorage 的 `bunny-garden-v1` 条目中。

| 根数据字段 | 备份内容 |
| --- | --- |
| `nickname`、`settings`、导航等字段 | 昵称、语速/音效/动效等设置、侧栏与导航选择 |
| 拼音字段、`hanzi`、`topics` | 拼音、汉字、语文及数学主题的学习位置、自评、收藏、错题、练习首答与历史；写作草稿、排序活动、拼音辅助与遮文偏好 |
| `phonics` | 英语课次、玩法、题量、语速、学习位置、练习过程与拼写草稿、自评、收藏、错题、练习历史及复习安排 |
| `rewards` | 三科共享的奖励事件、星星、已解锁物品、达标证据、展示选择、待庆祝队列及补发标记 |

课程、图片、音频属于应用静态资源，不是个人数据，不放进备份。仅处理应用的统一存储条目，不导出或覆盖同源下其他应用的数据；当前应用没有其他持久化存储。

导出读取当前内存中的完整根对象，因此浏览器禁止保存时也能备份当前练习结果。导入先完成全部校验，再通过统一入口执行一次 localStorage 写入。写入失败时保留原条目。

## 格式与兼容策略

备份入口为 `src/backup.js`：

- `format` 固定为 `bunny-learning-garden`，与其他 JSON 文件区分。
- `version` 表示备份结构版本，首版为 `1`，与应用发布版本独立。`exportedAt` 仅用于标明导出时间，不参与兼容判断。
- `producerVersion` 记录导出文件的应用版本，来自 `package.json` 并通过 Vite 注入；它只用于排查问题，不参与兼容判断，也不要求导入端与导出端版本一致。
- `data` 直接包含完整根对象，英语位于其 `phonics` 字段。根对象、英语字段及奖励数据保留各自的结构版本。
- 通过 `backupMigrations` 按备份版本选择导入路径；通过 `migrateGarden`、`migratePhonics` 处理根对象及英语字段的兼容和结构校验。
- 同一数据版本中新增加的可选字段由当前默认状态逐层补齐，不覆盖旧值；未知对象字段保留，不用白名单重建整个对象。既有加载器继续处理旧玩法等历史迁移，并按当前课程校验可恢复进度。
- 错误类型、危险属性以及不支持的备份、学习、英语或奖励数据版本都拒绝导入，不擅自降级或覆盖。新版导出的文件不保证能被旧版应用读取。

**旧备份兼容不是可以一劳永逸的自动承诺。** 当前已支持首版格式及其缺少新增可选字段的历史数据；未来真正发生结构变化时，必须实现并测试对应迁移，不能仅增加版本号。该约定要求后续版本保留已发布备份的读取能力。

## 后续开发要求

1. 在根对象中定义所有新增持久化字段，使它们随整份数据一起保存、导入和导出。
2. 增加可选设置或模块时提供默认值。重命名、删除字段或改变类型与语义时，提升相应数据版本并实现已发布版本到当前版本的迁移路径。
3. 保持课程、题目和奖励 ID 稳定；必须替换或合并 ID 时提供映射，不能直接依赖加载器过滤未知 ID，否则历史进度可能损失。
4. 奖励迁移保留事件 ID、解锁时间、达标证据和补发状态，导入后初始化不能因重复恢复而重复发星。
5. 固定保留 `tests/fixtures/backup-v1.json`，不可随新默认值重写。每次结构升级增加历史版本样本，验证旧文件导入、新字段默认值、原有记录及奖励保持，并覆盖导出后重新导入。
6. 在写入前拒绝不支持的版本与损坏数据。导入只执行一次完整写入，并验证存储失败时原记录保持不变。

## 验证

```sh
node --test tests/backup.test.mjs
npm run test:browser -- backup.spec.js
```

单元测试覆盖完整数据往返、固定 v1 备份补默认、奖励去重、未知版本及损坏数据拒绝、统一单次写入及失败保持原记录。浏览器测试覆盖实际文件下载与上传、覆盖确认与取消、跨模块保存、清空后的恢复及继续学习、刷新保持、失败提示和手机布局。
